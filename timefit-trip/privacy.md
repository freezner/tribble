# Tribble 개인정보 및 데이터 처리 안내

최종 갱신: 2026-10-29 · 현재 개발 소스 기준

> SNS 프로필 등록과 한 장씩 카드 공유는 TestFlight 1.1.1(35)에 포함됐습니다. 전체 카드 PNG 일괄 공유·사진 권한 안내·카드 타이틀·SNS별 이미지 규격 선택은 **TestFlight 1.1.1(37)**에 포함됐습니다. 이 문서는 현재 소스의 동작을 설명하며, 설치된 버전에 따라 이용 가능한 기능과 검색 제공자가 다를 수 있습니다. 문서 수정은 공개 원격 문서나 스토어 개인정보 항목의 반영 완료를 뜻하지 않습니다.

Tribble은 하루 여행의 장소, 체류 시간, 이동 시간과 여유 시간을 계획하는 앱입니다. 현재 계정 가입이나 자체 클라우드 동기화 기능은 없습니다.

## 앱 안에 보관하는 정보

여행 이름, 선택한 장소의 이름·주소·국가 코드·좌표·장소 제공자의 ID, 여행 날짜와 시간, 체류 시간, 교통수단, 직접 입력한 이동 시간, 초안과 언어 설정을 기기의 앱 저장소에 보관합니다. 생성·수정 시각과 재계산에 필요한 구간 상태도 보관합니다. 여행은 사용자가 삭제하기 전까지 유지되며 초안은 편집 중 자동으로 보관됩니다.

카카오가 반환한 자동 경로의 시간·거리·성공 계산시각은 여행 저장소에 영구 저장하지 않습니다. 현재 편집 중에는 메모리의 결과를 표시하고, 앱을 다시 실행해 여행을 열면 필요한 경로를 재조회합니다. 직접 입력한 시간은 그대로 보관합니다. 이전 버전의 Google·TMAP 계산값은 호환 처리하며 출처와 유효성에 따라 유지·폐기·재조회합니다. 아래 이미지 공유를 사용하면 화면에 표시된 계산 결과가 임시 이미지와 사용자가 전달한 사본에 포함될 수 있습니다.

선택적으로 등록한 SNS 프로필은 서비스명, 공개 사용자 이름, 정규화한 프로필 URL만 여행과 별도 저장소에 보관합니다. 비밀번호나 로그인 토큰은 받지 않습니다.

카드 이미지 상단에 표시할 이름이나 닉네임도 선택적으로 기기에 저장합니다. 여행·SNS 프로필과 각각 별도 저장소를 사용하며, 앞뒤 공백을 제거한 이름만 보관합니다. 빈값을 저장하면 카드에는 `tribble`을 표시합니다. 타이틀 설정만으로 이 이름이 중계 서버나 SNS에 전송되지 않지만, 이미지를 공유하거나 사진에 저장하면 카드의 일부로 포함됩니다.

앱은 이 데이터에 별도의 암호화 계층을 구현하지 않습니다. 기기의 운영체제 보호와 백업 설정이 적용될 수 있으므로, 모든 데이터가 암호화되거나 기기 밖으로 절대 이동하지 않는다고 보장하지 않습니다. 운영자가 전체 여행·SNS 프로필·카드 타이틀을 업로드받아 보관하는 클라우드 동기화 기능은 없습니다. 장소 검색·경로 계산에 필요한 일부 정보는 다음과 같이 중계 서버와 외부 제공자에 전송됩니다.

## 장소 검색과 이동 계산

현재 장소 검색은 대한민국 범위의 카카오 검색을 사용합니다. 검색어를 Tribble 중계 서버(`pastelinkers.com/tribble/api/places`)로 보내고 서버가 카카오에 조회합니다. 결과에서 장소를 선택할 때 별도 Google 상세 조회를 하지 않습니다.

국내 자동차·도보·대중교통·자전거 경로 계산에는 출발·도착 좌표, 교통수단, 계산 가능한 경우 일정의 구간 출발 시각을 중계 서버(`pastelinkers.com/tribble/api/route`)로 전송합니다. 서버는 필요한 좌표와 제공자가 지원하는 매개변수를 카카오·카카오모빌리티 API로 전달합니다. 현재 자동차는 기본적으로 현재 교통을 사용하며, 도보·자전거·대중교통에는 예정 출발 시각의 교통·시간표를 반영하는 요청을 보내지 않습니다. 여행 이름·전체 일정·SNS 프로필·카드 타이틀은 이 요청에 포함하지 않습니다.

중계 서버는 요청 처리 중 검색어·좌표·응답을 사용하지만 완료된 검색·경로 응답을 파일·데이터베이스나 재사용 캐시에 보관하지 않습니다. 동시에 진행 중인 동일 요청만 하나의 조회를 공유합니다. 요청 제한을 위해 접속 IP를 처리하며, 프로세스별 임의 값과 함께 해시한 식별자·요청 횟수·시각을 메모리에 보관합니다. 앱의 IP를 카카오 요청의 전달 헤더에 넣지는 않습니다.

프로젝트의 중계 서버 코드는 검색어·좌표·공급자 응답을 자체 로그에 남기지 않으며, 배포용 프록시 설정도 해당 경로의 접근 로그를 끕니다. 이는 호스팅 인프라의 운영·오류 기록이나 카카오·카카오모빌리티의 통신 기록이 없다는 뜻은 아닙니다. 제공자는 검색어·조회 좌표와 서버의 IP 등 통신 정보를 처리할 수 있습니다. 제공자 기록의 구체적 보관 기간은 이 앱 코드로 확인하거나 보장할 수 없습니다. [카카오 개인정보처리방침](https://www.kakao.com/policy/privacy), [카카오모빌리티 개인정보처리방침](https://policy.kakaomobility.com/viewer/?pageCode=PRIVACY_POLICY)을 참고해 주세요.

기존 해외 여행 등 카카오 국내 분기로 처리하지 않는 경로에는 Google Maps Platform 호환 조회가 남아 있습니다. 이 경우 앱이 출발·도착 장소 ID 또는 좌표, 교통수단과 지원되는 구간 출발 시각을 Google에 직접 전송합니다. Google은 요청 IP, URL과 매개변수, 시각, 응답 상태 등의 요청 기록을 보관한다고 안내하며 보관 기간은 목적과 정책에 따라 달라집니다. [Google Maps Platform의 데이터 수집·이용·보관 안내](https://developers.google.com/maps/security/compliance/security-compliance#data_collection_usage_and_retention), [Google 개인정보처리방침](https://policies.google.com/privacy)을 참고해 주세요.

현재 구현은 기기의 GPS나 현재 위치 센서를 읽지 않습니다. 선택 장소의 좌표는 사용자의 실시간 GPS 위치와 구별됩니다. 이전 1.1.0 계열에서 사용한 Google Places Autocomplete는 검색 지역을 지정하지 않았을 때 IP 기반 대략적 지역 편향을 사용했습니다. 현재 카카오 검색 흐름은 이 Google 자동완성을 호출하지 않습니다. [Google의 기존 자동완성 지역 편향 안내](https://developers.google.com/maps/documentation/places/web-service/legacy/autocomplete#locationbias)

## 외부 지도에서 경로·장소 확인

이동 구간의 외부 지도 버튼을 누르면 출발·도착 장소의 좌표와 교통수단을 길찾기 URL로 전달합니다. 두 장소가 한국으로 확인되는 구간은 카카오맵을, 그 외 구간은 Google Maps를 엽니다. 카카오맵에는 장소 이름도 전달하며, 앱에서 장소 이름을 수정했다면 수정한 이름이 포함됩니다. 외부 지도 앱이 설치되어 있지 않으면 브라우저에서 열릴 수 있습니다.

이 길찾기 동작은 사용자가 버튼을 눌렀을 때만 실행됩니다. Google API 키·Google 장소 ID·여행 전체 일정·일정의 출발 시각은 길찾기 URL에 포함하지 않습니다. 기기의 현재 GPS 위치를 읽어 전달하는 기능도 아닙니다. 외부 지도에서 출발 시각과 교통수단을 계획에 맞게 확인해 주세요.

일정 화면의 개별 장소명을 누르면 해당 장소의 저장된 좌표를 Google Maps 검색 URL로 전달합니다. 저장된 ID가 Google 장소 ID인 경우에는 그 ID도 함께 전달하며, 카카오 등 다른 제공자의 ID는 전달하지 않습니다. 사용자가 수정한 장소 이름·주소·여행 전체 일정·API 키는 이 장소 링크에 포함하지 않습니다. 장소 링크는 사용자가 누를 때만 열리며, Google Maps 앱을 사용할 수 없는 환경에서는 웹 지도가 열릴 수 있습니다.

외부 지도 서비스는 자체 정책에 따라 요청 및 통신 정보를 처리합니다. 외부 지도 화면에서 본 시간을 Tribble이 다시 읽어오는 기능은 없으며, 필요하면 사용자가 직접 입력합니다. 이는 앞서 설명한 API 자동 경로 계산과 별도 기능입니다. 자세한 내용은 [카카오 개인정보처리방침](https://www.kakao.com/policy/privacy) 및 [Google 개인정보처리방침](https://policies.google.com/privacy)을 확인해 주세요.

## SNS 프로필 등록

설정에서 Instagram·X·Facebook·TikTok의 공개 사용자 이름이나 프로필 주소를 입력할 수 있습니다. 저장 시 주소와 이름의 형식만 기기에서 검사하며 SNS 서버에 계정의 존재나 소유권을 확인하지 않습니다. 등록 정보만으로 SNS에 로그인하거나 게시 권한을 얻지 않으며 OAuth 인증·자동 게시 기능도 없습니다.

사용자가 프로필 열기를 누르면 저장한 공개 URL을 해당 앱이나 브라우저에서 엽니다. 이때 외부 서비스는 자체 정책에 따라 방문과 통신 정보를 처리할 수 있습니다. 등록·수정·삭제만으로 프로필 정보가 Tribble 중계 서버나 SNS에 전송되지는 않습니다.

## 이미지 공유

공유 기능은 사용자가 선택한 비율로 여행의 모든 카드 페이지를 PNG 임시 파일로 만든 뒤 한 번의 운영체제 공유 화면에 전달합니다. 이미지에는 카드 타이틀, 여행 이름, 방문 장소·순서, 날짜·시간, 체류·이동 정보와 추정 여부가 포함될 수 있습니다. 카드에 표시할 SNS 프로필을 선택하면 서비스명과 `@사용자 이름`도 이미지에 들어갑니다. 프로필을 선택하지 않고 공유할 수도 있습니다. 한 장씩 미리보더라도 공유 시에는 전체 페이지가 전달되므로 포함된 정보를 모두 확인해 주세요.

카드의 프로필 선택은 실제 게시 계정을 선택하거나 인증하는 동작이 아닙니다. 운영체제 공유창에서 대상 앱을 고른 뒤 해당 앱에서 사용할 계정·공개 범위·게시 내용을 직접 확인해 주세요. Tribble은 실제 게시 성공이나 게시 계정을 확인하지 않습니다. 공유를 취소하면 앱은 이를 게시 완료로 간주하지 않습니다.

공유 기능은 사용자의 기존 사진을 읽거나 사진 라이브러리를 탐색하지 않습니다. iOS에는 사용자가 공유창에서 사진 저장을 선택할 때 필요한 사진 추가 설명과, 포함된 공유 라이브러리의 사진 API 참조로 Apple이 요구하는 사진 보관함 접근 설명을 함께 선언합니다. 설명 문구의 선언만으로 권한이 허용되지는 않으며, 앱은 기존 사진 읽기 권한을 직접 요청하지 않습니다. 운영체제가 저장에 필요한 권한을 요청할 수 있고, 미리보기를 열거나 공유 버튼을 누르는 것만으로 사진 보관함에 자동 저장하지 않습니다.

iOS에서는 공유창 종료 후 임시 파일 정리를 시도합니다. Android에서는 수신 앱이 나중에 파일을 읽을 수 있도록 즉시 제거하지 않고 캡처 라이브러리·운영체제의 정리에 맡깁니다. 공유 대상 서비스의 데이터 처리는 해당 서비스의 정책을 따르며 사용자가 다른 앱에 전달하거나 사진에 저장한 이미지 사본은 그 서비스나 기기에 남을 수 있습니다. 사진 보관함에 저장한 사본에는 기기의 사진 동기화·백업 설정이 적용될 수 있습니다.

## 삭제와 설정

내 여행에서 개별 여행을 삭제할 수 있고, 설정에서 저장된 여행과 초안을 모두 삭제할 수 있습니다. 언어 설정·SNS 프로필·카드 타이틀은 여행 삭제와 별도로 보관됩니다. SNS 프로필은 설정에서 각 프로필을 편집한 뒤 삭제할 수 있으며, 이는 기기에 등록한 정보만 지우고 SNS 계정 자체를 삭제하지 않습니다. 카드 타이틀은 설정의 입력란을 비운 뒤 저장하면 등록한 이름을 지우고 기본값으로 되돌립니다. 이전 여행 저장 형식의 복구용 사본을 보관하는 경우, 명시적인 여행 삭제 시 해당 사본에도 삭제를 반영합니다.

앱에서 여행·프로필·카드 타이틀을 삭제해도 이미 공유하거나 사진에 저장한 이미지, SNS 게시물, 외부 지도 기록이나 제공자가 보관하는 요청 기록은 삭제되지 않습니다. 사진이나 게시물은 저장한 앱에서 별도로 삭제해야 합니다. Tribble은 해당 서비스에 삭제 요청을 보내는 기능을 제공하지 않습니다.

삭제 작업이 실패하면 앱에 오류가 표시됩니다. 앱을 제거하거나 운영체제에서 앱 데이터를 초기화할 때 데이터가 처리되는 방식은 기기의 백업 및 복원 설정에 따라 달라질 수 있습니다.
