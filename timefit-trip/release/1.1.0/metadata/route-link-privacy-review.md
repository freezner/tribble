# 1.1.0 외부 지도 연결과 개인정보 신고 검토

검토일: 2026-10-27. 이번 경로 복구 수정을 포함한 로컬 소스 기준이며, 이 문서 작성으로 스토어 신고나 원격 문서를 변경하지 않았습니다.

## 앱 내부 요청과 외부 탐색

| 흐름 | 전송과 처리 | 신고 판단 |
| --- | --- | --- |
| 앱 내부 Google REST 요청 | 장소 검색·선택·지원 구간 계산에서 검색어, 장소 ID 또는 좌표, 교통수단 등을 전송합니다. Google의 요청 로그와 IP 기반 지역 편향은 기존 데이터 흐름입니다. | 기존 `SearchHistory`, `OtherUsageData`, `OtherDiagnosticData`, `CoarseLocation` 신고를 유지합니다. 외부 지도 예외를 여기에 적용하지 않습니다. |
| 사용자 버튼으로 외부 지도 열기 | `Linking.openURL`로 카카오맵 또는 Google Maps 앱/웹에 이동합니다. 출발·도착 좌표와 교통수단을 전달하며 카카오맵에는 표시 이름도 전달합니다. 사용자가 수정한 이름도 포함됩니다. Google API 키·Google 장소 ID·여행 전체·일정 출발 시각은 URL에 넣지 않습니다. | 앱 내부 REST 수집과 구분되는 사용자 주도 외부 탐색으로 판단합니다. 개인정보 안내에는 수신 서비스와 전달값을 명시합니다. |
| 지도 확인 후 시간 입력 | 지도에서 확인한 시간을 사용자가 Tribble에 직접 입력합니다. 지도 결과를 자동 수집하거나 가져오지 않습니다. | 신규 위치 센서·광고 식별자·SDK 수집은 추가되지 않았습니다. 선택한 목적지 좌표를 사용자의 실제 현재 위치와 동일시하지 않습니다. |

## App Store 판단

현재 구조에는 카카오 SDK·REST 호출·앱이 제어하는 WebView가 없으며, 이름이 표시된 외부 지도 버튼을 사용자가 눌러 별도 앱/웹으로 이동합니다. Apple은 제3자 파트너를 앱에 포함한 외부 업체 코드 등의 범위로 설명하고, 웹 탐색을 허용하는 트래픽을 앱이 제어하는 수집과 구분합니다. 이 외부 탐색의 성격과 기존 앱 내부 요청이 유지되는 점을 근거로 **기존 네 가지 데이터 유형·목적·연결·추적 답변을 유지하는 판단**입니다. 새 `OtherUserContent` 또는 `PreciseLocation` 유형이 반드시 생겼다고 보지는 않습니다.

이는 Apple의 선택적 신고 면제 네 조건을 모두 충족한다는 주장이 아닙니다. 수정 가능한 장소 이름이 외부 서비스에 전달된다는 사실은 `privacy.md`에 명시했습니다. 외부 지도의 화면·계정·쿠키·보관 처리는 해당 서비스 정책에 따르며, Tribble이 그 수집 전체를 제어하거나 확인한다고 설명하지 않습니다.

향후 지도 SDK, 앱 내부 WebView 제어, 직접 경로 API, 외부 지도 결과 자동 수집, 광고 연계가 추가되면 이 판단을 다시 검토해야 합니다. 근거: [Apple App Privacy Details](https://developer.apple.com/app-store/app-privacy-details/).

## Google Play 판단

Google Play는 제3자 앱으로의 전달을 기본적으로 공유에 포함하지만, 사용자가 예상할 수 있는 명시적인 사용자 주도 전달은 공유 신고 예외로 설명합니다. 이번 이름이 표시된 지도 버튼은 이 예외에 해당한다고 판단할 근거가 있습니다. 다만 이 예외로 기존 Google 검색·경로 REST 요청이나 로그 수집까지 제외하지 않습니다. 기존 Android 데이터 보안 메모의 자동 요청 수집 검토는 별도로 유지하며, Play 최종 양식은 실제 출시 바이너리와 함께 확인해야 합니다.

근거: [Google Play 데이터 보안의 수집·공유 정의와 사용자 주도 전달 예외](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en), [카카오 개인정보처리방침](https://www.kakao.com/policy/privacy).
